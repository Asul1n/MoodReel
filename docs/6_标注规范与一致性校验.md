# 标注规范与一致性校验

本文件是 ABSA（方面级情感分析）数据集的人工标注准则，也是论文「数据标注」
一节的依据。所有标注者必须**先完整读完本文件、完成试标、通过一次性一致性
检查**，再开始正式标注。

- 方面体系定义在代码里：`backend/app/services/aspects.py`（唯一真源，本文与
  代码冲突时以代码为准，并请提 issue 修正本文）
- 抽样脚本：`backend/scripts/sample_annotation.py`
- 一致性校验：`backend/scripts/compute_kappa.py`

---

## 1. 为什么需要这一步

现有系统的情感分析停留在**整句极性**（positive / negative），数据表
`reviews.ground_truth` 在真实库里**全为空**——也就是说，此前所有指标都是在
无标签数据上"看起来合理"，没有一条可复算的准确率。

这带来两个无法回避的问题：

1. **没有评估基准**。任何模型（TextCNN、DeepSeek、词典规则）都无法报
   P/R/F1，因为不存在"正确答案"。
2. **无法支撑"方面级"这一主张**。一条影评说「演技在线，剧情稀碎」，整句极性
   只能是 0 或勉强取主导，掩盖了真正有价值的信息：观众到底在夸什么、骂什么。
   前面 `group_divergence` 的天花板效应（效应量中位数 0.777）根源就在这里——
   分组依据是星级、度量是整句极性，两者同源，测出来的只是"打分高低"的
   另一种写法。

因此阶段 0 的目标是产出一份**小规模但可信**的方面级标注集，作为后续 ABSA
抽取器的训练与评估基准。规模不追求大，追求**可复算、一致性可验证**。

## 2. 产出规格

| 文件 | 条数 | 谁标 | 用途 |
|---|---|---|---|
| `backend/data/annotation/annotation_train.csv` | 240 | 1 人 | 训练 / few-shot 示例 |
| `backend/data/annotation/annotation_test_raterA.csv` | 60 | 标注者 A | 测试集 + 一致性 |
| `backend/data/annotation/annotation_test_raterB.csv` | 60 | 标注者 B | 一致性（**盲标**） |
| `backend/data/annotation/sample_meta.json` | — | 脚本生成 | 复现用（seed、id 列表） |

分层方式：按 `stars` 五层比例分配（1★ 34 / 2★ 22 / 3★ 38 / 4★ 58 / 5★ 88 进
train，测试集 9 / 5 / 10 / 14 / 22），层内按影片轮转抽样，共覆盖 44 部影片。
`seed=42`，同库同 seed 可完全复现。

**测试集两份文件内容完全相同，且都不含任何人的答案。** 若标注者 B 能看到 A
的结果，测出的是"协商后的一致性"，不是"独立判断的一致性"，不能作为标注
质量的证据。这一点在论文里必须写明，否则审稿人会质疑 Kappa 的可信度。

**为何只有 60 条双标**：双标的作用是估计标注噪声，60 条足以把 Kappa 的标准误
控制在 0.1 以内；全量 300 条双标要把工作量翻倍，但不会让噪声估计显著更准。

## 3. 表格怎么填

每行一条评论，需要填 9 列：

| 列 | 取值 | 说明 |
|---|---|---|
| `sent_polarity` | `+` / `0` / `-` | 整句对**这部电影整体**的态度 |
| `asp_plot` | `+` / `0` / `-` / `NA` | 剧情 |
| `asp_act` | 同上 | 表演 |
| `asp_vis` | 同上 | 视听 |
| `asp_pace` | 同上 | 节奏 |
| `asp_music` | 同上 | 配乐 |
| `asp_theme` | 同上 | 主题 |
| `evidence` | 见 §6 | 证据片段，可留空 |
| `note` | 自由文本 | 拿不准时写理由，供仲裁用 |
| `annotator` | 你的代号 | 如 `A` / `B` |

**`NA` 与空白的区别**：空白 = 还没看/漏填；`NA` = 已判定"这条评论没有提到
这个方面"。校验脚本把整行全空视为漏标并剔除，但**单个方面的空白会被当成
未提及**，所以没提到的方面请显式写 `NA`（或直接用 Excel 下拉填充）。

`stars` 列是原始星级，**仅供参考，不得直接照抄成极性**。标注的目标是判断
评论文字表达的态度，而不是复述打分——豆瓣上大量"五星差评"（反讽）和
"一星力荐"（自嘲式喜欢），照抄星级会把这些全标错，也会让评估退化成
"星级分类"，失去意义。

## 4. 六个方面的定义

按"**评的是电影的哪个零件**"划分，不按句子的语法主语划分。

### 4.1 剧情 `plot` / story

剧本结构、情节合理性、叙事手法、改编忠实度、逻辑漏洞。

- 正例：`故事讲得很完整，最后二十分钟的反转完全没猜到`
- 负例：`逻辑漏洞太多，人物动机站不住脚`
- **归 plot 的词**：剧情、故事、剧本、情节、叙事、改编、设定、结局、伏笔、
  转折、套路、桥段

### 4.2 表演 `act` / acting

演员的演技与角色塑造：表情、台词功底、情绪传递、选角是否贴脸、演员外形
是否契合角色。

- 正例：`黄渤把这个小人物的隐忍演得入木三分`
- 负例：`全程面瘫，台词像在念稿`
- **边界**：演员**外形/气质与角色是否契合**归 act（属于选角）；**服化道、
  妆造、打光**归 vis。
- 只评价"某某好帅"且与角色无关 → `NA`，note 写 `fan`。

### 4.3 视听 `vis` / visual

画面与影像呈现：摄影、构图、色调、特效、服化道、美术、镜头语言。

- 正例：`沙漠那场戏的光影处理太漂亮了`
- 负例：`五毛特效，抠图边缘都在飘`
- **边界**：剪辑**节奏**归 pace；剪辑造成的**叙事混乱**归 plot；纯**画面
  切换手法**（长镜头、转场设计）归 vis。

### 4.4 节奏 `pace` / pacing

叙事节奏与剪辑：是否拖沓、是否仓促、时长是否合适、是否让人看困。

- 正例：`两小时一点都不觉得长，全程没看手机`
- 负例：`中段拖沓到犯困，恨不得快进`
- **边界**：因**看不懂**而不适归 plot；因**慢/闷/长**而不适归 pace。
  "无聊" 默认归 pace，除非上下文明确说"故事无聊"（则 plot）。

### 4.5 配乐 `music` / music

配乐与音效：主题曲、插曲、背景音乐、声音设计。

- 正例：`片尾曲一响直接绷不住了`
- 负例：`配乐全程铺得太满，吵得听不清台词`
- **边界**：只提"歌好听"但指的是 OST 本身而非影片 → 仍归 music（它是影片的
  一部分）。声音**技术问题**（听不清、爆音）归 music。

### 4.6 主题 `theme` / theme

主题立意与情感共鸣：想表达什么、价值观、思想深度、是否打动人。

- 正例：`讲的是父子关系，看完给我妈打了电话`
- 负例：`强行煽情，价值观也很拧巴`
- **边界**：**没有明确对象的情感反应**归 theme（"看完久久不能平静"、
  "哭了一整场"）；但若前文明确了对象（"因为配乐哭了"），归对应方面。

### 4.7 不在集合内的内容

评论提到但六类都不覆盖的（如"票价太贵""影院空调太冷""字幕翻译差"）：
六个方面全填 `NA`，`note` 写 `other: 具体内容`。**不要硬塞进最近的方面**，
硬塞会污染该类别的定义，让 Kappa 与后续抽取都失真。

## 5. 极性怎么判

| 编码 | 含义 | 判定 |
|---|---|---|
| `+` | 明确正面 | 有褒义评价、推荐、称赞、满足 |
| `-` | 明确负面 | 有批评、贬义、失望、抱怨 |
| `0` | 中性或不可分混合 | 客观陈述；或同一方面同时褒贬且无法分出主次 |
| `NA` | 未提及 | 这条评论没有涉及该方面 |

### 5.1 分句拆标优先于整体 0

「演技在线，剧情稀碎」→ `act=+`、`plot=-`，**不是** `plot=0`。

只有当**同一个方面在同一处**同时出现褒贬、且无法拆分时，才用 `0`。
例：「剧情前半段很抓人，后半段垮了」——这是 plot 内部的转折，若两侧分量
相当标 `0`，明显偏一侧则标该侧。

### 5.2 否定

否定负面词 = 正面：「不无聊」→ pace `+`；「不算烂片」→ 整句 `+`（弱正面，
仍记 `+`，不用 `0` 表示"弱"）。

否定正面词 = 负面：「没什么惊喜」→ `-`。

双重否定按语义还原：「不是不好看」→ `+`。

### 5.3 转折与让步

「本来是冲着演技来的，结果剧情拉胯」——转折后的分句才是真实评价。
若两侧都评价了不同方面，各自按本句标；若评价同一方面，**以转折后为准**。

### 5.4 反讽

按**说话人真实意图**标，不按字面。「真是绝了，烂得清新脱俗」→ `-`。
反讽较隐蔽时在 `note` 写 `irony`。

### 5.5 假设与期待

「如果剧情再紧凑点就完美了」——这是**隐含批评**，plot 标 `-`。

「希望能有续集」——是期待而非对现有内容的评价，相关方面标 `NA`。

区分标准：**是否在指出现有作品的缺陷**。指出缺陷 → `-`；仅表达愿望 → `NA`。

### 5.6 转述他人观点

「有人说剧情拖沓，我倒觉得还好」——本条标注的是**评论者本人**的态度，
plot 标 `+`（或 `0`），`note` 写 `quote`。不要把被转述的观点当作评论者观点。

### 5.7 行为反应可间接推断

「我昨天在电影院睡着了」→ pace `-`（或 plot `-`，取决于上下文线索），
`note` 写 `inferred`。**允许推断，但必须在 note 标明**，便于后续统计
"推断型标注"占比。

### 5.8 只描述不评价

「本片 2014 年上映，片长 169 分钟」→ 全 `NA`。信息陈述不构成情感。

### 5.9 剧透

剧透本身不影响极性判断，按正常规则标。不要因为"被剧透"而给负面。

## 6. 证据片段 `evidence`

格式：`方面key:原文片段`，多个用 `;` 分隔。

```
act:黄渤演得入木三分;plot:最后二十分钟反转没猜到
```

规则：

1. **必须逐字摘自原文**，不改写、不概括、不补标点。
2. 尽量短，够定位即可（10–30 字），但**不能短到丢失极性**。
   「演技」两个字不构成证据；「演技在线」可以。
3. 片段里的 `;` 和 `:` 请用全角 `；` `：`，否则会破坏解析。
4. 一条评论里同一方面只取一处最典型的证据，不要求穷举。
5. `train` 集不强制填证据（工作量考虑）；`test` 集**建议填**，用于评估
   抽取器的证据定位质量。

## 7. 操作流程

### 第 0 步：试标（约 30 分钟，必做）

从 `annotation_test_raterA.csv` **前 10 条**开始，A、B 各自独立标完，然后
对照讨论：

```bash
cd backend
# 用前 10 条做一个临时小表
python - <<'PY'
import csv
rows = list(csv.DictReader(open('data/annotation/annotation_test_raterA.csv', encoding='utf-8-sig')))
with open('data/annotation/_pilot.csv', 'w', encoding='utf-8-sig', newline='') as f:
    w = csv.DictWriter(f, fieldnames=list(rows[0].keys()))
    w.writeheader(); w.writerows(rows[:10])
PY
```

对答案时**只讨论分歧条目、只改规范不改答案**。若发现某条规则确实没写清，
把它补进本文第 4、5 节——这是唯一允许修改规范的时机。

### 第 1 步：正式标注

- `train` 240 条：1 人标，**分 5 批**，每批约 48 条，单批不超过 45 分钟。
  连续标超过 1 小时会出现一致性漂移（越标越松或越严），这是标注质量最
  常见的隐性杀手。
- `test` 60 条：A、B 各标一份，**互不查看**，标完再交换。
- 每批标完立刻保存，不要在 Excel 里开自动更正（会把 `+` `-` 当公式）。

### 第 2 步：校验

```bash
cd backend
python scripts/compute_kappa.py \
  --a data/annotation/annotation_test_raterA.csv \
  --b data/annotation/annotation_test_raterB.csv
```

输出 `kappa_report.md` 与 `disagreements.csv`。

### 第 3 步：处理不达标

**Kappa 门槛：方面宏平均 κ ≥ 0.70**（Landis & Koch 的 "substantial" 下限，
NLP 标注常用门槛）。

未达标时按分歧构成定位问题，**不要直接重标全部**：

| 现象 | 原因 | 处理 |
|---|---|---|
| mention 分歧 ≫ polarity 分歧 | 「什么算提到了该方面」定义不清 | 修订 §4 边界条款，只重标分歧涉及方面 |
| polarity 分歧集中在 `0` 与 `-` 之间 | 中性/负面的边界模糊 | 在 §5 增补该方面的具体例子 |
| 某一两个方面 κ 特别低 | 该方面定义与其他方面重叠 | 检查是否与相邻方面职责冲突（如 plot/pace） |
| 整体 κ 都不高但 po 很高 | prevalence 效应，非真实分歧 | 看 PABAK 与条件 κ，如实报告，不强行调数据 |

修订规范后只重标**分歧条目 + 该方面相关的条目**，并在论文中记录修订次数
（"规范迭代 1 次后 κ 由 x 升至 y"是加分项，说明流程严谨）。

## 8. 报告口径（论文写作要点）

`compute_kappa.py` 输出四个指标，**论文里应同时给出，不可只挑一个**：

- **po**（原始一致率）：直观但不扣随机基线。
- **Cohen's κ**：扣除随机一致，但受 prevalence 影响。
- **PABAK**（2·po − 1）：不受类别分布影响的替代指标。
- **条件 κ**：仅在两方都判"提及"的样本上算极性一致性，把"提没提"与
  "极性对不对"两类误差分开。

必须在论文中写明 Kappa 悖论的存在：方面标注里 `NA` 占比常超 80%，此时
κ 会被系统性压低，而 PABAK 与条件 κ 更接近真实一致性。只报 κ 而不解释，
容易被质疑"一致性不达标"；只报 PABAK 而不报 κ，则显得在挑好看的数字。
两个都报并说明差异，才是诚实的做法。

另外要报告：**测试集 60 条的 Kappa 置信区间较宽**（标准误约 0.08–0.12），
不宜宣称"κ 精确等于 0.74"。可用 bootstrap 给出区间，或在文中说明样本量限制。

## 9. 常见错误清单

- ❌ 照着 `stars` 填极性 → 评估变成星级分类，ABSA 的意义消失
- ❌ 把"剧情拖沓"标成 plot → 应为 pace（评价的是"看着累不累"）
- ❌ 用 `0` 表示"弱正面/弱负面" → `0` 只表示中性或不可分混合
- ❌ 一句话只标一个方面 → 一句话可以同时涉及多个方面，各自标
- ❌ 证据片段自己概括 → 必须逐字摘自原文，否则无法验证抽取器定位
- ❌ A、B 边标边讨论 → 一致性失真，Kappa 虚高
- ❌ 空白代替 `NA` → 校验时无法区分"未提及"与"漏填"
- ❌ 把"票价贵""影院差"硬塞进某个方面 → 记 `other`，不要污染类别定义
