# 1_开发工作流规范

> 定义 AI 的开发规则。**Git 协作流程以 `README.md` §6 为唯一权威**（分支模型 / 开工 pull / 合并 / 铁律），本文档不重复，只补充代码层面的规则。

## 1. 总原则

1. **文档优先**：动代码前先读 `0_总览与导航.md` 与规格文档。
2. **数据库唯一真理**：规格 §4 + `backend/app/models.py`。
3. **接口唯一真理**：规格 §6 + `backend/app/schemas.py`。
4. **一次只做一件事**，不顺手改无关代码；**可运行优先**，不写伪代码占位。

## 2. 代码风格

### Python（后端）

- PEP 8，4 空格缩进；函数写 type hints 与 docstring。
- 命名：类 `PascalCase`、函数/变量 `snake_case`、常量 `UPPER_SNAKE_CASE`。
- 分层：路由层只做参数校验 + 调 service；业务逻辑放 `services/`、`crawler/`；ORM 用 `models.py`，请求/响应用 `schemas.py`。

### ArkTS（前端 App）

- 命名：组件/类 `PascalCase`，变量/函数 `camelCase`。
- HTTP 统一走 `services/http.ts`，页面里不直接写 http 调用；接口封装在 `services/api.ts`（改契约只动这里）。
- 数据模型放 `model/`，与 `backend/app/schemas.py` 字段对齐。
- 图表统一走 `components/charts/`（Canvas 自绘），词云走 `components/wordcloud/`。

## 3. 禁止行为（红线）

| ❌ 禁止 | ✅ 替代 |
|---------|--------|
| 硬编码密钥 / 密码 | 放 `.env`（`TENCENT_APPID` 等），`config.py` 读取 |
| 擅自改表结构 | 先改规格 §4 + `models.py`，再改代码 |
| 擅自改接口路径/字段 | 先改规格 §6 + `schemas.py`，前后端同步 |
| 前端硬编码后端地址 | 放设置页（Preferences），默认读常量 |
| 提交无法启动的代码 | 至少 `pytest -q` 通过 + 单接口冒烟 |
| 提交大文件 | `*.db`、`*.npz`、IMDB csv 不入库（`.gitignore` 已配） |

## 4. Git 提交规范

- 与 README §6 一致，Conventional Commits：`feat:` / `fix:` / `docs:` / `chore:`。
- 一次提交一件事；`backend/` 与 `app/` 的改动尽量分开提交。

## 5. 密钥与敏感信息

- 密钥写 `backend/.env`（从 `.env.example` 复制），`.env` 已 `.gitignore`。
- 训练产物 `backend/models/*.npz`、数据库 `*.db` 不入库，单独共享。

## 6. 交付检查清单

- [ ] 能启动 / 能编译 / `pytest` 通过
- [ ] 字段名与规格 §4/§6、`models.py`/`schemas.py` 一致
- [ ] 无硬编码密钥；日志无敏感信息
- [ ] 遵循命名与分层规范
- [ ] 若改动接口/表结构，已同步规格文档
- [ ] 提交信息带前缀，一次一件事
