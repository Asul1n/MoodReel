# 鸿蒙前端设计说明（成员C）

> 与 **`app/README.md`** 和**规格 §5.4** 一致。前端工程为 `app/mood_reel_GUI`（DevEco Studio 生成）。本文档为成员C 的前端开发依据。

## 1. 技术栈

| 项 | 选择 |
|----|------|
| 语言 | ArkTS（ArkUI 声明式） |
| IDE | DevEco Studio，Empty Ability，Compatible SDK ≥ API 10 |
| 图表 | **ArkUI Canvas 自绘**（不依赖 ECharts / 第三方图表 SDK） |
| 词云 | 后端 `/viz/wordcloud` 渲染 PNG，前端 `Image` 直接加载 |
| 网络 | `@kit.NetworkKit`（`http.createHttp`）封装为单一模块 `services/http.ets` |

## 2. 页面规划（落地为 2 个 Tab + 登录注册页）

实际实现为 `pages/Index.ets` 下的两个 `TabContent`：**TabHome**（单页多分区承载主流程）与 **TabSettings**（本地偏好 + 用户），外加独立页面 **AuthPage**（登录/注册）。**游客模式**：开屏后未登录自动进入登录/注册页（底部提供「游客进入」入口），未登录可用全部主流程；设置页用户卡片亦可随时进入登录。

| 页面 | 功能分区 | 主要后端接口 |
|------|------|--------------|
| Tab1 主页（TabHome） | 「为你推荐」横滑卡片（登录→个性化标签推荐，游客/冷启动→热点，点卡片直达分析）→ 搜索/选片 → 发起抓取 → 轮询进度 → 影片信息（简介/海报/评分）→ 情感分布（环形图）→ 评论情感列表（分页/展开）→ Top 热点词（条形图）→ 褒贬倾向词 → 词云（PNG）→ 评论趋势 | `GET /recommend`、`GET /crawl/movies`、`GET /crawl/movie/{id}`、`POST /crawl`、`GET /crawl/{id}`、`POST /analyze/backfill`、`GET /dataset/stats`、`GET /dataset/reviews`、`GET /hotspot`、`GET /viz/summary`、`GET /viz/wordcloud` |
| Tab2 设置（TabSettings） | 用户卡片（未登录→去登录；已登录→用户名+退出登录）、后端地址 + 测试连接、夜间模式、采集源切换 | `GET /health` |
| 登录/注册页（pages/AuthPage） | 蓝白渐变简洁风；登录/注册模式切换、表单校验（用户名 3~20 字符、密码 6~20 位、两次一致）、注册成功自动登录、底部「游客进入」 | `POST /auth/register`、`POST /auth/login` |

## 3. 模块划分（entry/src/main/ets/）

```
pages/              # Index（Tabs 容器）、SplashPage、AuthPage（登录/注册）
views/              # TabHome（主流程单页）、TabSettings
services/
  http.ets          # @kit.NetworkKit 封装（getText/postText，超时/错误码/JSON，自动附带 Authorization）
  api.ets           # 接口类型化封装（真实 HTTP，改后端契约只动这里）
components/
  charts/           # Canvas 自绘：RingChart / BarChart / PolarityCompare / TrendChart
  RevealCard.ets    # 入场动效卡片
model/              # ArkTS 数据类型（Models.ets，与 backend schemas 对齐）
common/             # 常量（Constants.ets：BASE_URL 等）
```

## 4. 图表方案（Canvas 自绘）

- **环形图**：正负情感占比；**条形图**：Top 热点词；**褒贬对比**：`polarity.pos/neg` 两列对照；**趋势双柱图**（TrendChart，Steam 风格每日双柱、横向滚动）：按月的评论数量与正负走势（时间优先取评论原始发表时间 `review_time`，缺省回退入库时间 `created_at`）。
- **词云**：后端 `wordcloud` 库渲染 PNG（`/viz/wordcloud?context=…&top_n=40`），前端 `Image` 加载，不做端侧排版。
- 数据来自聚合接口 `GET /viz/summary?context=`（后端一次算好返回，App 只渲染）。

## 5. 关键约定

- 后端地址集中在 `common/Constants.ets` 的 `BASE_URL` 一处，联调时改为宿主机局域网 IP。
- 网络权限：`module.json5` 声明 `ohos.permission.INTERNET`；开发期放开明文 http。
- HTTP 客户端封装成单一模块，便于联调替换与统一报错；`api.ets` 已接入真实后端（非 MOCK）。
- 分析上下文：`whole`（IMDB 整库）/ `movie:{id}`（某部影片），主页各分区跟随当前影片。
- 登录态（游客模式）：`authToken` / `authUsername` 存 `AppStorage` 并经 `PersistentStorage` 持久化（`EntryAbility.onCreate` 初始化）；`http.ets` 在本地有 token 时对**所有**请求自动附 `Authorization: Bearer <token>`，/auth 之外接口不读该头。
