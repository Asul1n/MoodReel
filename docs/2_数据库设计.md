# 2_数据库设计

> 数据库结构以**规格文档 §4** 与 **`backend/app/models.py`** 为唯一真理（三者一致）。本文档为便于查阅的汇总，字段如有出入以 `models.py` 实际代码为准。

## 1. 选型与约定

| 项 | 决定 |
|----|------|
| 数据库 | SQLite（默认 `backend/data/moodreel.db`，路径见 `.env.example` 的 `MOODREEL_DB`） |
| ORM | SQLAlchemy 2.x（`Mapped` + `mapped_column` 声明式） |
| 主键 | `movies.movie_id`、`crawl_jobs.job_id` 为**字符串**；`reviews.id` 整型自增 |
| 时间 | `DateTime`，`datetime.utcnow` |
| 表 | `movies` / `reviews` / `crawl_jobs`（+ 可选缓存表 `hotspot_cache`） |

## 3. 情感字段约定（重要）

- `pred_label` 为**统一二类口径**：`positive` / `negative`（英文 TextCNN 与中文 DeepSeek 一致）。
  - **不设 neutral 档**：很中性的评论也判为正或负，靠**低置信度（趋近 0.5）表达"中性/犹豫"**；
  - 豆瓣 3 星（"还行"）不派极性，与完全无标签的评论一起归 `unlabeled`（单独统计，不入正负）。
- `pred_prob` 是置信度 / 方向强度 **0~1**：越接近 0.5 越中性、越接近 1 情感越强；**仅模型判定有值**，星级 / ground_truth 这类人工标签为 NULL。
- `model` 标注引擎：`textcnn`（英文本地）/ `deepseek`（中文，唯一在线通道）/ `static`（IMDB 静态）/ `stars`（星级定性）。

## 4. 分析上下文

- `whole`：IMDB 静态整库样本（`movie_id` 为空）。
- `movie:{movie_id}`：某部动态采集影片。
情感 / 热点 / 可视化接口均跟随 `context` 参数。
